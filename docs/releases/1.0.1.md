# 1.0.1 compatibility patch

Status: **released 2026-10-11**. This is a patch increment, not the optional
planning/TDD runner. Qualification results are in the
[release qualification record](../validation/2026-10-11/release-qualification.md).

The candidate retains kickoff, checkpoint, resume, audit and closeout, legacy
Markdown state versions 1–3, and the existing `bash scripts/itworks-lint.sh [root]`
interface. Normal runtime uses Bash 3.2+, POSIX awk and standard Unix tools.
Python and Go are development-test dependencies only.

## Behavior changes

Malformed alternate/indented findings and incomplete profile/heading matches can
no longer disappear. Acceptance records need nonempty user wording and precise
one-to-one finding linkage. Genuine historical ambiguity is a read-only warning;
it blocks strict critical gates/counts until reviewed. Missing legacy fields and
Revisit when remain drift, never invented consent or an automatic rewrite.

One parser supplies validation, strict gate eligibility and lifetime publication
counts. Diagnostics do not print finding text or quotes. Contextual secret
review distinguishes private configuration from tracked/served/history exposure.
Candidate mutation tests use explicit disposable copies; task restore points
preserve unrelated staged/unstaged work. Audit currency advances only after
completed declared scope; all closeout observations precede reckoning and gate.

## Existing-user advisory

Update with `claude plugin marketplace update itworks` and
`claude plugin update itworks@itworks`. The cached 1.0.0 to 1.0.1 upgrade was
checked on Claude Code 2.1.296 (macOS); see the
[host checklist](../../tests/host/claude-upgrade-smoke.md).

After an authorized update, begin a fresh host session. Verify the session-start
version **and loaded artifact identity**, then run:

```bash
bash "<installed-plugin-root>/scripts/itworks-lint.sh" "<project-root>"
```

This is read-only. Previously shipped projects, especially those with manually
edited findings or acceptances, should review newly detected errors before the
next deployment. Old reports and SHIPPED entries remain history; they are not
fresh proof under corrected checks. Never delete `.itworks`, rewrite accepted
quotations or recreate SHIPPED merely to obtain a green result. Preserve the
user's severity and words. Follow the [external-backup recovery procedure](../../references/upgrade-recovery.md)
before authorized repair. Ambiguous acceptance requires ordinary user review,
not guessed linkage; supported additive v1/v2 drift does not require kickoff.
