# 1.0.2 audit patch

Status: **released 2026-10-13**. Instruction-only changes to `project-audit` and
`references/audit-method.md`. No state format change, no new runtime dependency,
and the lint, hooks and other four skills are unchanged.

## Why

The first audit of a third-party repo showed the audit was written for the
user's own project. It had no path for a repo without itworks set up, wrote
reports into the code under review, let reviewers run a stranger's code, and lost
three security lanes to safety-filter cut-offs while their reports were written.

## Behavior changes

- **Trigger.** "Audit this repo" or "audit <path>" starts the skill even with no
  `.itworks/`. The method file now says to start the skill instead of following it
  by hand.
- **Outside repos.** A new Step 0 asks, when unclear, whether the target is the
  user's project or an outside repo. For an outside repo, state and reports go in
  `<parent>/<repo-name>-audit/`, minimal state is written without an owner
  interview, and the target tree is never written to. There is no fix wave; the
  confirmed findings are the deliverable.
- **Untrusted code.** Reviewers only read. Verifiers run code only in a sandbox
  with no network (a VM with no network interface is the tested pattern), or fall
  back to traced code paths with execution-only items as coverage gaps. The scope
  line names the isolation.
- **Cut-off reports.** Findings are appended one at a time, reproductions are
  worded as tests, and each report or verification file ends with a fixed
  completion line. The orchestrator checks the file, not the agent's summary. In
  the audit that found the problem, this re-ran the three lost lanes and seven
  verifications with no cut-offs.
- **Lane approval.** An approved plan that contains the lane table is the approval.
- **Per-finding lens.** `Lens id:` in LANES.md is now `Default lens id:`; a finding
  may carry its own. Existing LANES.md files keep working.
- **Agreeable verifiers.** Each reproduction carries a control case that passes on
  correct code. A lane where nothing was refuted (three or more items) gets a blind
  re-check of up to three confirmed items by a verifier that has not seen the
  earlier reasoning.

## Upgrading

`claude plugin marketplace update itworks`, then
`claude plugin update itworks@itworks`, then start a fresh session. Users still on
1.0.0 should read the [1.0.1 advisory](1.0.1.md) first.
