## Patch interfaces agreed before implementation

- Existing `bash scripts/itworks-lint.sh <project-root>` retains human diagnostics, final error/warning summary, exit 0 for valid-with-warnings and exit 1 for invalid/unreadable state. The wrapper performs no edits.
- New `bash scripts/itworks-state.sh check|gate|counts <project-root>` uses new `scripts/itworks-state.awk`, requiring only existing shell/core utilities and POSIX awk. No jq, Python or GNU-only awk extension. All three operations are read-only. `check` evaluates the existing state contract plus precisely documented fixes; `gate` additionally assesses whether recorded critical closures/acceptances can support release; `counts` additionally reads the optional archive and produces publishable lifetime counts only when interpretation is valid and critical acceptance linkage is not blocked. A successful gate is necessary, not sufficient, for release: it does not prove checks ran, user speech occurred or all risks were discovered.
- Internal stdout protocol is UTF-8 TSV, version 1. First record: `FORMAT\t1`. Diagnostics: `ERROR|WARN|BLOCKED\t<stable-code>\t<encoded-relative-path>\t<line-number>\t<encoded-safe-message>`. Counts: `COUNT\t<key>\t<nonnegative-decimal>`, with keys exactly `found`, `fixed`, `accepted`, `critical_open`, `critical_accepted`. Final record: `SUMMARY\t<error-count>\t<warning-count>\t<blocked-count>`. Percent-encode `%`, tab, CR and LF in text columns; diagnostics never include full finding descriptions, user quotations, credential values or file contents. A caller must require a complete supported FORMAT/SUMMARY and successful process exit; partial output is not a valid result.
- `check`: exit 0 or 1; zero BLOCKED records. `gate` and `counts`: exit 0 eligible, 1 invalid/I/O failure, 2 otherwise-valid but blocked evidence. Unknown operation/argument shape: exit 64, usage on stderr, no protocol stdout. Counts are buffered and emitted only on exit 0; invalid/blocked input cannot produce a plausible all-zero count payload. Diagnostics may precede failure. `critical_open>0` blocks gate; counts may report open critical numbers accurately because the receiving contract explicitly represents them. Publication remains subject to its existing post-closeout and consent sequence, never authorized merely by `counts`.
- Legacy acceptance matching uses the accepted finding's complete description field and the entry's finding-text field after trimming surrounding whitespace only. No fuzzy, case-insensitive, substring or date-only match. One accepted finding must map to one unique entry; one entry cannot waive two findings. Original Markdown stays untouched. Empty/no acceptance section is the existing structural error. A nonempty historical section with missing/ambiguous linkage is a check warning; unresolved critical linkage blocks gate/counts rather than rebuilding all project state. Missing `Revisit when:` remains a legacy warning. Exact linkage and nonempty user wording establish record consistency, not independent proof of consent.
- Unit suite: `python3 -m unittest discover -s tests/unit -p 'test_*.py'`. Integration suite: `python3 -m unittest discover -s tests/integration -p 'test_*.py'`. All fixture mutations occur under TemporaryDirectory. Default suites never invoke a real model, reach the network, change the caller repository/index/config, or print synthetic credential values. Live host acceptance is a separately selected, explicitly provisioned activity.
